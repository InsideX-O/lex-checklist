# Как выпускать релизы Lex

Репозиторий: `InsideX-O/lex-checklist`, ветка `main`. Внутри четыре файла:

| Файл | Что это |
|---|---|
| `lex-checklist.html` | сама карточка (приложение + встроенная база) |
| `pack-redwood.json` | пакет базы законов Redwood — отдельно от карточки |
| `version.json` | что сейчас актуально: версия карточки и версия базы |
| `RELEASES.md` | эта инструкция |

У карточки две независимые версии:

- **APP_VERSION** (`1.0`, `1.1`, …) — код, интерфейс, логика. Меняется только с новым файлом карточки.
- **DB_VERSION** (`redwood-1.0`, `redwood-1.1`, …) — база законов. Обновляется у людей прямо в открытой карточке, без скачивания нового файла.

## version.json — шаблон

```json
{
  "app": {
    "version": "1.0",
    "date": "2026-09-24",
    "changelog": ["Что поменялось в карточке — по строке на пункт"]
  },
  "db": {
    "server": "redwood",
    "version": "redwood-1.0",
    "date": "2026-09-24",
    "changelog": ["Что поменялось в базе — по строке на пункт"]
  },
  "minAppVersion": "1.0"
}
```

`changelog` — всегда **список строк** в квадратных скобках, даже если пункт один.
Необязательные поля: `app.html_url`, `db.pack_url` — если файл лежит не по стандартному адресу.

## Обновил только базу (статьи, санкции, CFG)

1. Открой карточку → «Выгрузить текущую базу». Скачается `pack-redwood.json` (имя уже правильное, переименовывать не нужно).
2. Внеси правки в статьи этого файла.
3. GitHub: заменить `pack-redwood.json` → Commit.
4. В `version.json`: поднять `db.version` (`redwood-1.0` → `redwood-1.1`), обновить `db.date`, в `db.changelog` перечислить правки → Commit.
5. Всё. У пользователей при открытии: «Доступна база redwood версии redwood-1.1» со списком изменений и кнопкой «Обновить базу сейчас».

**Порядок коммитов важен: сначала пакет, потом `version.json`.** Иначе кто-то успеет увидеть новую версию и скачать старый пакет.

## Обновил приложение (код, интерфейс, логика)

1. Правь `case-checklist-v1.0.html`.
2. Подними `APP_VERSION` в файле (`1.0` → `1.1`) и `APP_DATE`.
3. Если встроенная в файл база тоже свежая — выставь `DB_VERSION` и `DB_DATE` в файле равными текущим `db.version` / `db.date` из `version.json`. Иначе новая карточка сразу предложит «обновить базу» до той же версии.
4. GitHub: заменить `lex-checklist.html` → Commit.
5. В `version.json`: поднять `app.version` до `1.1`, обновить `app.date`, в `app.changelog` перечислить правки → Commit.
6. Всё. У пользователей при открытии: «Доступна карточка версии 1.1» и кнопка «Скачать новую карточку».

## Обновил и то и то

1. Обнови базу (шаги 1–4 выше).
2. Обнови карточку (шаги 1–6 выше).
3. Если новый код использует новые поля в базе — в `version.json` подними `minAppVersion` до новой `APP_VERSION`. Тогда на старой карточке кнопки «Обновить базу» не будет, вместо неё предупреждение «Сначала скачайте новую карточку».

## Правила версий

- Версии только растут. Сравнение идёт по числам: `redwood-1.10` новее `redwood-1.9`, `redwood-2.0` новее `redwood-1.9`.
- Префикс сервера (`redwood-`) не меняй — по нему видно, к какому серверу база.
- Обновление базы, принятое в браузере, живёт, пока оно новее встроенной `DB_VERSION` карточки. Вышла карточка с базой новее — старое принятое обновление отбрасывается само.
- Без интернета карточка работает как раньше: проверка при открытии молчит, ошибка видна только по кнопке «Проверить обновления».

## Автоматизация через n8n (план)

ИИ-агент в n8n будет обновлять базу сам — по тем же шагам, что «Обновил только базу»:

1. Забрать из репозитория текущие `pack-redwood.json` и `version.json`.
2. Внести правки в `LAW_DB` пакета. Каждая запись: `law`, `article`, `text` (строка) и дальше `chapter`, `attrs`. Статью не терять, дубликатов «закон + номер» не плодить.
3. Проверить пакет перед заливкой: `LAW_DB` — непустой массив, у каждой записи есть `law`, `article` и `text`-строка. Такую же проверку делает сама карточка — битый пакет она отклонит и не применит.
4. Закоммитить `pack-redwood.json`.
5. Только после этого закоммитить `version.json`: `db.version` +0.1, `db.date` — сегодня, `db.changelog` — короткие строки по каждой правке («ст. 12.8 УАК — новая санкция»).
6. Токен GitHub хранится только в учётных данных n8n. В карточку и в репозиторий его не класть.
7. Код карточки (`lex-checklist.html`) агент не трогает — это ручной релиз.
